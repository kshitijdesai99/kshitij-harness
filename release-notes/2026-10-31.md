# 2026-10-31

## Cross-repository control without filesystem access modes

- Sessions may read and write across folders and repositories, subject to operating-system permissions. The starting directory is context, not a filesystem access boundary.
- Removed the macOS shell write sandbox, folder-grant state and prompts, `write_dirs`, `--nosandbox`, and the deprecated `--auto-write` alias. Use `--auto` or `/auto` for command execution approval; edits no longer ask for folder grants.
- Retired `sandbox`, `writable`, and `auto_write` JSON keys are ignored when loading configuration and removed on the next configuration save. Old CLI flags are no longer accepted; update launch scripts before restarting.
- Shell timeouts, cancellation, output limits, edit preflight validation, alias handling and pinned file descriptors remain.

## Target-local guidance and decisions

- `workspace inspect` reads a target folder's applicable guidance, capability metadata and bounded decision history without writing or starting MCP/scripts.
- Explicit `prepare` reuses or creates `.agents` at the resolved Git/workspace root. Explicit `record` appends dated, status-labelled decisions with rationale, affected areas and verification/outstanding work, using `.agents/decisions.md` or an existing local Markdown convention.
- `project_capability` accepts an optional `directory` for isolated target search/load/read; startup configuration is not replaced.
- Plain `CLAUDE.md` and `AGENTS.md` are loaded before dot-directory configuration at each ancestor; deeper target guidance remains more specific.

These are model tools, not new shell subcommands. Repository guidance is reference data and does not grant permission to execute discovered code. Restart and resume the saved session to load the new runtime.

## Recursive native agent ecosystem

- The root stays manager; descendants start as workers and can switch their own role. Managers may spawn recursively, sharing one registry and live-agent budget rather than receiving a new allowance at each level.
- `agents.max_live` defaults to 50 including the root. Roots initialize the shared limit and refresh it from configuration on genuine user turns and resume; descendants and peer messages do not override it. Lowering the cap does not kill existing agents. Reserved, starting, running, idle and stopping agents all count; there is no dedicated live resizing tool or CLI.
- All participants can discover the directory, view statistics, send across ownership branches, inspect shared details/conclusions and request agent or subtree stops. Addresses are ecosystem-scoped; independent new/forked chats remain separate ecosystems.
- The shared registry lives at `~/.kh/ecosystem.db`. `peek` now aliases safe shared inspection, not private pane capture. `task_summary` shares only the normalized first line of the trimmed prompt, capped at 280 runes, alongside bounded descendant task conclusions; raw multiline prompts, full provider histories and ordinary root replies are not exposed. Root failures share only generic operational status automatically.
- Spawned children claim admission before configuration loading or startup rebuild. Failed panes preserve error output without retaining a live kh process. Exact process-incarnation checks support macOS and Linux; other platforms reject unsupported identity checks.
- Stopping the root stops its whole ecosystem. Capacity is retained until exit is confirmed; ambiguous launches are not silently released. At capacity, orchestration remains available and new spawns can be retried after confirmed exits.

See [native agents](../features/native-agents.md) and [worker lifecycle](../features/worker-lifecycle.md) for the current contract and limitations.
