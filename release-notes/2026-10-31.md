# 2026-10-31

## Cross-repository control without filesystem access modes

- Sessions may read and write across folders and repositories, subject to operating-system permissions. The starting directory is context, not a filesystem access boundary.
- Removed the macOS shell write sandbox, folder-grant state and prompts, `write_dirs`, `--nosandbox`, and the deprecated `--auto-write` alias. Use `--auto` or `/auto` for command execution approval; edits no longer ask for folder grants.
- Retired `sandbox`, `writable`, and `auto_write` JSON keys are ignored when loading configuration and removed on the next configuration save. Old CLI flags are no longer accepted; update launch scripts before restarting.
- Shell timeouts, cancellation, output limits, edit preflight validation, alias handling and pinned file descriptors remain.

## Target-local guidance and decisions

- `workspace inspect` reads a target folder's applicable guidance, capability metadata and bounded decision history without writing or starting MCP/scripts.
- Explicit `prepare` reuses or creates `.agents` at the resolved Git/workspace root. Explicit `record` appends dated, status-labelled decisions with rationale, affected areas and verification/outstanding work, using `.agents/decisions.md` or an existing local Markdown convention.
- `project_capability` accepts an optional `directory` for isolated target search/load/read; startup configuration is not replaced.
- Plain `CLAUDE.md` and `AGENTS.md` are loaded before dot-directory configuration at each ancestor; deeper target guidance remains more specific.

These are model tools, not new shell subcommands. Repository guidance is reference data and does not grant permission to execute discovered code. Restart and resume the saved session to load the new runtime.
