# Release notes: 2026-11-05

## Assigned task startup banner

- Native descendants now show **ASSIGNED TASK — agent name** and the full task in explicit bold cyan before activity/progress setup and model/tool work, in both headless and interactive modes.
- Long tasks wrap naturally and multiline assignments remain complete. Redirected output and color-disabled terminals stay plain; interactive descendants no longer echo a duplicate initial query. Ordinary root output is unchanged.
- This is a [startup scrollback banner](../features/terminal-feedback.md#assigned-task-startup-banner), not a pinned header. Launcher rebuilding and earlier session/memory setup can precede it.

## Project-aware, task-fresh workers

- Native delegation accepts [bounded structured handoffs](../features/native-agents.md#task-handoffs) instead of copying parent conversations. Explicit `assign` starts a fresh task; `send` remains same-task steering and coordination.
- Opt-in `spawn` with `reuse: true` can reuse a compatible idle worker or launch one. [Idle retirement](../features/worker-lifecycle.md#task-fresh-reuse) defaults to 60 seconds, with 0 disabling retirement; ordinary spawning and plain-task `keep` are unchanged. Structured handoffs with `keep` are rejected; use `reuse` for task-fresh follow-ups. Process identities and task lease generations fence late results, and idle workers still consume capacity.
- [Assignment foundations](../features/project-configuration.md#assignment-foundations) cache validated project configuration within a process, refresh after source changes, and return independent snapshots. Matching identifiers do not mean cross-process cached state, shared histories or execution authority.
- An explicit [verified-state Git push](../features/shell.md#verified-git-push) workflow checks the expected committed state and clean working tree, pushes one pinned commit to its configured upstream branch without force, and confirms the remote commit. Prior verification references are required; the workflow does not rerun tests or infer authority from a free-form push request.
- [Assignment phase timings](../features/turn-metrics.md#assignment-phase-timings) distinguish startup, context, execution and reporting from provider turn metrics. Roughly ten seconds for an already-verified push is a target, not a guarantee or a measured performance claim.
