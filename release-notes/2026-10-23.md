# Release notes: 2026-10-23

User-facing changes in kh.

## Memory

- Added opt-in hybrid retrieval with local Qwen3-Embedding 0.6B and Qwen3-Reranker 0.6B. `/memory hybrid on` sets up and verifies both; `/memory hybrid off` restores keyword-only search without deleting cached models or vectors.
- Added database-native procedural references with names, aliases, version history, and shareable exports. Full procedures and inert script assets load on demand; retrieval and imports never execute them.
- Fixed reranker queue exhaustion during worker bursts. Queue and inference limits now fit within the client deadline, with cancellation and keyword fallback preserved.
- Allowed managed hybrid runtime files through the macOS shell sandbox without granting writes to config, login files, or unrelated folders.
- Fallback notices now distinguish embedding failures from reranking failures.
- Added compact per-message retrieval diagnostics: stage counts, loaded memories, and elapsed time. `/memory explain` shows full candidate IDs, scores, and rejection details from the last retrieval without rerunning it.
- Automatic topic recall skips common standalone greetings, check-ins, and acknowledgments, and avoids embedding/reranking when all requested knowledge is already in the chat. Corrections, required summary notes, and explicit named references are preserved.
- Hybrid search now uses type-labeled memories and task-applicability scoring, rejecting weak matches and low-scoring tails before applying memory quotas. Semantic candidates below the standalone similarity floor can reach the bounded reranker. Keyword-only retrieval and failure fallbacks remain supported. Automatic recall reduces its candidate budget to 32 or the configured kind reservations, whichever is larger (35 with defaults), within the existing 64-document ceiling. Explicit search retains its 64-document budget.
- Managed helper revisions now cover the exact Python source, including its scoring prompt. Authenticated health checks, revision-pinned scoring requests, and explicit graceful upgrades prevent silently reusing a stale prompt or different builds automatically replacing one another. No saved PIDs are signaled and unknown listeners are never stopped. Legacy helpers need a one-time manual stop before adopting this lifecycle.
- Compaction now explicitly treats retrieved memories and tool/peer reports as reference data, omitting unrelated recalled topics rather than promoting them into user goals.

## Chat and documentation

- Interactive chat and automatic command/folder approval are now the defaults. Use `-p "TASK"` for headless work or `--auto=false` for approval prompts; sandbox restrictions still apply.
- Updated the README and memory architecture diagram for hybrid setup, reranking, and procedural references.
- Organized release notes in `release-notes/YYYY-MM-DD.md` files, with one file per date.
- Kept the memory architecture diagram as SVG only, removing the duplicate PNG.
