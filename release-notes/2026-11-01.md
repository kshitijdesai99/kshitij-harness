# Release notes: 2026-11-01

User-facing changes in kh.

## Session connector inventory

- `/connector` lists [session MCP startup snapshots](../features/project-configuration.md#session-connector-inventory), advertised-tool counts, resource/prompt availability, and conservative service hints from discovered tool names.
- It performs no live probes, reconnection, authorization, or model requests. Registered availability does not prove product authentication, permissions, or live health; generic gateway tools may not reveal every connected service. Restart to refresh the snapshot.

## Manager delegation policy

- Every manager, including promoted descendants, now receives explicit [delegation duties](../features/native-agents.md#human-as-ceo-main-agent-as-manager): assign implementation/integration edits, routine tests, builds, installation and restart execution to workers, then coordinate and assess their evidence. On promotion, hand existing execution tasks to workers before continuing.
- Role-conditional instructions reach new/resumed roots and descendants, including custom system prompts; native-tool promotion also supplies a manager reminder without changing CLI JSON output. Finished workers or full capacity do not justify manager execution or role-switching workarounds. Ordinary informational answers and bounded evidence inspection remain allowed. This is operating policy, not a hard tool ban or scheduler.

## Native MCP OAuth

- Trusted Streamable HTTP MCP servers can use [generic native OAuth](../features/project-configuration.md#native-http-oauth): protected-resource and authorization-server discovery, dynamic public-client registration, and authorization code login with S256 PKCE and a loopback callback. No provider-specific bridge is required for compatible servers.
- Browser login requires an interactive root chat and explicit consent, even with auto approval enabled. Headless sessions and delegated agents use cached credentials/refresh only; tool calls never open a browser.
- Credentials use a private, unencrypted `~/.kh/mcp/oauth` cache with atomic writes and cross-process refresh locking. Explicit `Authorization` headers still take precedence; configured MCP headers are not forwarded to OAuth endpoints. Existing trust and tool-approval controls remain unchanged. See the canonical guide for compatibility and security limits.
